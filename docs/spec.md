## 1. 개요

### 1.1 배경
- 경쟁사 앱 벤치마킹, 자사 앱 UX 점검, 사용성 테스트 결과 정리 시 화면 녹화 영상을 사람이 일일이 돌려보며 화면을 캡처하고 플로우를 손으로 그리는 작업이 반복됨
- 영상 1개(2~3분) 정리에 평균 1~2시간 소요 → 자동화 시 10분 이내 목표

### 1.2 목적
화면 녹화 영상 → 구조화된 UX 분석 산출물 자동 변환. 사람은 검수·해석에만 집중.

### 1.3 타깃 사용자
- 주 사용자: UX 디자이너, 서비스 기획자
- 부 사용자: QA(시나리오 검증), 개발자(화면 전환 명세 확인)

### 1.4 핵심 산출물 (사용자 요구 기준)
1. **화면 인벤토리** — 등장한 고유 화면 캡처 + 화면명 + 구성 요소
2. **화면 흐름도** — 화면 전환 시퀀스 다이어그램 자동 생성
3. **단계별 행동 로그** — 탭/입력/스크롤 등 행동 타임라인
4. **UX 문제점 진단** — 이탈·헤맴·오류 지점 및 개선 제안

## 2. 사용자 시나리오

> 기획자 A가 경쟁사 송금 플로우 녹화 영상(.mp4)을 업로드한다. 5분 후 분석 완료 알림을 받고, 화면 12개의 인벤토리, 송금 플로우 다이어그램, 47개 행동 이벤트 로그, "OTP 입력 화면에서 14초 체류 — 평균 대비 3배" 같은 진단을 확인한다. 결과를 Markdown 리포트로 내보내 팀 위키에 붙인다.

## 3. 분석 파이프라인 설계

```
[영상 업로드]
   → ① 전처리: ffmpeg로 프레임 추출 (장면 전환 감지 + 0.5초 간격 샘플링)
   → ② 키프레임 선별: perceptual hash로 중복 프레임 제거
   → ③ 화면 인식: 멀티모달 LLM이 각 키프레임을 분석
        - 화면 분류 (로그인 / 홈 / 목록 / 상세 / 입력폼 / 팝업 / 로딩 / 오류 …)
        - OCR + UI 요소 식별 (버튼, 입력란, 탭바 등)
        - 동일 화면 클러스터링 → 고유 화면 인벤토리 확정
   → ④ 행동 추론: 연속 프레임 diff로 이벤트 추정
        - 탭(요소 하이라이트/화면 전환), 텍스트 입력(필드 값 변화),
          스크롤(콘텐츠 이동), 뒤로가기, 대기
   → ⑤ 플로우 구성: 화면 노드 + 전환 엣지 → Mermaid 다이어그램 생성
   → ⑥ UX 진단: 휴리스틱 + LLM
        - 휴리스틱: 화면별 체류시간, 백트래킹(되돌아감) 횟수, 동일 화면 재방문,
          오류/빈 화면 노출, 입력 재시도
        - LLM: 휴리스틱 신호 + 화면 맥락 종합 → 문제점 서술 및 개선 제안
   → ⑦ 리포트 조립 & 저장
```

**왜 LLM 비전인가**: 좌표 기반 UI 자동화 도구와 달리 입력이 영상뿐이므로(터치 좌표 메타데이터 없음), 화면 의미 이해·요소 식별·행동 추론 모두 비전 모델이 필요. 휴리스틱(해시, diff)으로 비용을 줄이고 LLM 호출은 키프레임에만 수행.

## 4. 기능 명세

우선순위: **P0** = MVP 필수 / P1 = 1차 고도화 / P2 = 이후

### F-01. 영상 업로드 (P0)
| 항목 | 내용 |
|---|---|
| 설명 | 드래그&드롭 또는 파일 선택으로 영상 업로드 |
| 입력 | mp4, mov, webm / 최대 500MB / 최대 10분 |
| 처리 | 업로드 즉시 분석 큐 등록, 진행률 표시 |
| 인수조건 | 지원 외 포맷·초과 용량 시 명확한 오류 메시지. 업로드~분석 시작까지 5초 이내 |

### F-02. 프레임 추출 & 키프레임 선별 (P0)
| 항목 | 내용 |
|---|---|
| 설명 | 장면 전환 감지(ffmpeg scene filter) + 고정 간격 샘플링 병행 후 pHash로 중복 제거 |
| 출력 | 타임스탬프가 매핑된 키프레임 시퀀스 |
| 인수조건 | 화면 전환 누락률 5% 이하(검증셋 기준), 3분 영상 기준 키프레임 30~100장으로 압축 |

### F-03. 화면 인식 & 화면 인벤토리 (P0)
| 항목 | 내용 |
|---|---|
| 설명 | 키프레임별 화면 유형 분류, 화면명 자동 작명, OCR, 주요 UI 요소 목록화. 동일 화면 클러스터링으로 고유 화면 도출 |
| 출력 | 화면 카드: 대표 캡처, 화면명, 유형, 핵심 요소, 등장 구간(타임스탬프) |
| 인수조건 | 고유 화면 분리 정확도 90% 이상(동일 화면을 다른 화면으로 중복 생성하지 않음). 화면명은 사용자가 인라인 수정 가능 |

### F-04. 행동 이벤트 추론 & 단계별 행동 로그 (P0)
| 항목 | 내용 |
|---|---|
| 설명 | 프레임 간 변화로 사용자 행동(탭, 입력, 스크롤, 뒤로가기, 대기) 추론 |
| 출력 | 타임라인 테이블: `시각 / 화면 / 행동 / 대상 요소 / 비고`, 각 행 클릭 시 해당 프레임 미리보기 |
| 인수조건 | 화면 전환을 유발한 행동은 100% 로그에 포함. 추론 신뢰도 낮은 행동은 "추정" 표기 |

### F-05. 화면 흐름도 자동 생성 (P0)
| 항목 | 내용 |
|---|---|
| 설명 | 고유 화면을 노드, 전환을 엣지로 하는 플로우 다이어그램 생성 (Mermaid) |
| 출력 | 인터랙티브 다이어그램(노드 클릭 → 화면 캡처/로그 연동), Mermaid 소스·PNG 내보내기 |
| 옵션 | 전환 횟수 엣지 라벨, 방문 순서 번호, 백트래킹 엣지 강조 |
| 인수조건 | 로그의 모든 화면 전환이 다이어그램에 반영. 화면 20개 이하에서 가독성 유지(자동 레이아웃) |

### F-06. UX 문제점 진단 (P0)
| 항목 | 내용 |
|---|---|
| 설명 | 휴리스틱 신호 + LLM 종합 분석으로 문제 지점 도출 |
| 진단 항목 | ① 과도한 체류(헤맴 의심) ② 백트래킹/재방문 ③ 오류·빈 화면 노출 ④ 입력 재시도 ⑤ 과도한 단계 수(목표 대비 깊은 뎁스) |
| 출력 | 진단 카드: 심각도(High/Mid/Low), 발생 지점(타임스탬프+화면), 근거, 개선 제안 |
| 인수조건 | 모든 진단에 근거 프레임 링크 포함. 단일 영상 한계(n=1) 고지 문구 표시 |

### F-07. 결과 뷰어 & 리포트 내보내기 (P0)
| 항목 | 내용 |
|---|---|
| 설명 | 분석 결과 4종을 탭으로 제공하는 웹 뷰어 + 내보내기 |
| 내보내기 | Markdown(이미지 포함 zip), PDF / P1: PPTX 요약 |
| 인수조건 | 내보낸 문서 단독으로 4종 산출물 모두 열람 가능 |

### F-08. 프로젝트 & 분석 이력 관리 (P1)
- 분석 건을 프로젝트(예: "경쟁사 송금 벤치마킹")로 묶어 관리, 목록·검색·재열람
- 동일 플로우의 영상 2건 비교 보기(자사 vs 경쟁사 화면 수·단계 수·체류시간 비교) — P2

### F-09. 인증·보안·관리 (P0 — 사내 도구 필수)
- 사내 SSO 연동, 부서 단위 접근 제어
- **민감정보 마스킹**: 금융앱 녹화 특성상 계좌번호·이름·잔액 등이 프레임에 노출될 수 있음 → 분석 시 자동 감지·블러 처리 옵션(기본 ON), 원본 영상 보존 기한(기본 30일) 후 자동 삭제
- LLM 호출은 사내 승인된 API 경로만 사용, 외부 학습 미사용 계약 확인

## 5. 서비스 화면 구성 (도구 자체 UI)

| 화면 | 주요 요소 |
|---|---|
| S-1 업로드 홈 | 드래그&드롭 영역, 최근 분석 목록, 분석 옵션(마스킹 on/off, 샘플링 간격) |
| S-2 분석 진행 | 단계별 진행 상태(추출→인식→플로우→진단), 예상 잔여 시간 |
| S-3 결과 뷰어 | 좌: 영상 플레이어(타임스탬프 동기화) / 우: 탭 4개(인벤토리·흐름도·행동 로그·UX 진단) |
| S-4 프로젝트 목록 | 프로젝트/분석 건 검색·필터 (P1) |

핵심 인터랙션: **모든 산출물 ↔ 영상 타임스탬프 양방향 연동** (로그 행 클릭 → 영상 해당 시점 이동, 영상 재생 → 로그 하이라이트)

## 6. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 성능 | 3분 영상 기준 전체 분석 10분 이내 |
| 비용 | LLM 호출은 키프레임 한정, 영상 1건당 분석 비용 상한 설정 가능 |
| 정확도 운영 | 사용자가 화면명·플로우·로그를 수정하면 결과에 즉시 반영(수동 보정 기능) |
| 보안 | F-09 참조. 분석 데이터는 사내망 스토리지에만 저장 |
| 가용성 | 업무시간 기준 운영, 분석 실패 시 단계별 재시도 |

## 7. 데이터 모델 (요약)

```
Project ─< Analysis ─< Frame(timestamp, image, phash)
                   ─< Screen(name, type, elements[], representative_frame)
                   ─< Event(timestamp, type, screen_id, target, confidence)
                   ─< Transition(from_screen, to_screen, event_id)
                   ─< Finding(severity, type, evidence_frames[], suggestion)
```

## 8. 기술 스택 (제안)

| 레이어 | 기술 |
|---|---|
| 프론트 | React + Mermaid.js(흐름도) + 영상 플레이어 |
| 백엔드 | Python FastAPI + 작업 큐(Celery/Redis) |
| 영상 처리 | ffmpeg(프레임 추출·장면 감지), OpenCV/imagehash(diff·pHash) |
| AI | 멀티모달 LLM API(화면 인식·행동 추론·진단), 필요시 경량 OCR 보조 |
| 저장 | 사내 오브젝트 스토리지 + PostgreSQL |

## 10. 리스크 & 한계

| 리스크 | 대응 |
|---|---|
| 터치 좌표가 영상에 없음 → 행동 추론 정확도 한계 | "탭 표시(터치 포인터)" 켜고 녹화하도록 가이드 제공 시 정확도 대폭 상승. 추론 신뢰도 표기 |
| 동적 콘텐츠(애니메이션, 배너)로 동일 화면이 다르게 인식 | 클러스터링 임계값 튜닝 + 사용자 병합 기능 |
| LLM 비용/속도 | 키프레임 압축 강화, 화면 인식은 경량 모델 → 진단만 상위 모델 |
| 민감정보 유출 | 자동 마스킹 기본 ON, 보존 기한, 사내망 한정 |
| n=1 영상 기반 진단의 과잉 일반화 | 진단 문구에 한계 고지, 비교 분석(P2)으로 보완 |
